# 使用指南（V12.2.0）

本指南面向面板使用者，按“登录 → 账号 → 项目配置 → 兼容日期 → 部署/更新 → 任务跟踪 → 自动检查 → 数据管理”的顺序说明。

## 1. 登录与账号

- 打开 HTTPS 面板，使用应用自身的 `ACCESS_CODE` 登录。它不是 Cloudflare API Token，也不能用于调用 Cloudflare API。
- 会话 Cookie 带 `Secure`/`HttpOnly`；写请求自动携带会话绑定的 CSRF token。不要把 Cookie、`ACCESS_CODE` 或业务账号的 API Token 发到公开问题区。
- 打开“账号工具 → 添加账号”：
  - **Account ID**：Cloudflare 账号的 32 位十六进制 ID（不是邮箱、不是域名）。
  - **别名**：面板内唯一标识；重名别名会被拒绝，不能靠修改别名合并账号。
  - **认证方式**：推荐最小权限的 API Token；也可使用 Global API Key + 登录邮箱。两者在前端都只显示掩码。
- “刷新用量”查询各账号当日请求量与配额；用量失败不影响账号本身，可稍后重试。
- “移除账号”只移除中控里的账号配置和凭据，不会删除 Cloudflare 账号、Worker 或 KV。删除远端资源是另一类需要确认的操作。

## 2. 项目配置

面板顶部可切换三个项目：**CMliu / Joey / ECH**。每个项目的配置互相独立，包括：

- 上游代码源：仓库内文件路径、分支/标签（留空用自动探测）。
- 变量与 Secret 列表、UUID、ADMIN 密码等模板参数。
- 目标 Worker 名称（账号编辑表单里按模板维护 `workers_*`）。
- 部署历史/收藏/固定版本。
- 兼容日期（见下一节）。

编辑配置时请记住：

1. 表单里的修改只是**草稿**，点击保存后才写入服务器。
2. 保存返回冲突（409）时，先重新读取最新配置，比较并合并后再保存；不要用旧页面强行覆盖。
3. 保存请求超时不代表没写入：保留原意图，按原请求核对，不要反复创建新的保存。
4. 旧页面/旧客户端缺少配置协议头时服务端返回 428，刷新页面即可。

## 3. 兼容日期（V12.2.0 新功能）

每个项目面板顶部有一行：

```text
兼容日期  [2026-01-20]  [保存]   状态文字
```

- 三个项目分别保存，互不影响。
- 默认值：CMliu `2024-04-05`、Joey `2026-01-20`、ECH `2024-04-05`。
- 只有真实日历日期且不早于 `2021-11-01`、不晚于今天才能保存。
- 保存成功后状态显示“已保存 日期”；下一次部署、更新或 1101 修复会使用新日期。
- **已经接纳的任务不会改变**：任务规划时会把日期冻结进执行计划，这是为了保证重试/重放时使用同一份 Cloudflare 配置。如果你刚保存日期而旧任务还在跑，请等它结束或新建任务。
- 保存遇到 409（配置冲突）时刷新页面/该配置后重新保存；不要重复使用旧 revision。

## 4. 部署与更新

1. 选择项目，确认变量和上游版本。
2. 点击“预览”查看将影响的账号、Worker、版本与绑定差异。
3. 确认后“部署更新”；批量部署需要选择目标账号和 Worker 名称。
4. 返回 202 表示**已进入持久任务链**，必须到任务列表查看执行结果。按钮恢复、请求超时、关闭面板都不会取消任务。
5. 任务成功后，可到 Cloudflare 控制台核对 Worker 的脚本、绑定、`compatibility_date` 与域名；中控展示的是执行回执与读回结果。

批量部署/新建 Worker 注意事项：

- Worker 名称必须符合 Cloudflare 命名规则（小写字母、数字、`-`，长度限制）。
- 启用 KV 绑定时会创建或复用同名 namespace；不要在别的账号复用同名但不同内容的 KV。
- 自定义域名需要账号已配置 zone；绑定失败会留在步骤事实里，不代表已回滚已创建资源。

## 5. 任务列表与状态

- 任务面板默认收起；图标徽标表示有新任务或待确认请求。
- 展开后可按状态查看：排队、执行中、完成、部分失败、失败、待核对。
- 详情里能看到每个目标账号的步骤：上传、配置域名、修改子域名、清理 KV 等，以及每步的 `verified`/`failed`/`unknown`。
- `unknown` **不是普通失败**：表示外部写结果未知。此时不要重复点击部署，等待维护人员通过固定 GET 观察和人工裁决处理。
- 任务终态为 `succeeded` / `partial_failed` / `failed` / `cancelled`；`partial_failed` 表示部分目标成功，需按失败原因分别处理。

## 6. 1101 修复

1. 在项目中点击“一键修复 1101”，先确认目标清单（必须与当前安装的完整清单一致）。
2. 可选择“保留受保护账号的账号级子域名”；默认会保留中控/受保护资源，不允许对它们执行删除重建。
3. 修复会先备份目标脚本、绑定、域名和子域名，再删除、重传、回读、恢复域名。
4. 帐号级子域名默认采用非破坏方式：先 PUT 并回读；只有在供应商明确拒绝时才会删除重建，失败会尝试恢复旧名。
5. 任务接纳后在任务列表跟踪；不要在修复进行中再次发起同类修复，否则会产生重复计划。

## 7. 自动检查与通知

- 打开“自动任务设置”抽屉：启用开关、检查间隔（1–1440 分钟）、参与模板、熔断阈值（0–100%）、告警 Webhook（https）。
- 保存后由 Cloudflare Cron 触发检查；平台不保证精确到秒，页面上的“上次检查”只是已保存的运行记录，不代表上次成功部署。
- 版本检查发现上游更新会创建部署任务；失败目标按策略重试；达到熔断阈值会暂停对应 UUID 轮换并按配置发送通知。
- 通知失败不自动证明业务任务失败；两者状态在任务面板/工作台中分开显示。

## 8. 账号用量、诊断与工作台

- “刷新用量”使用账号凭据查询当日请求量；日配额上限可在账号编辑中设置，超过阈值时触发熔断判断。
- 工作台显示即时操作日志、诊断、上游源码摘要和脱敏报障；它是即时反馈，不是持久任务回执。
- “诊断”检查 KV/DO 绑定、配置读取等关键路径；诊断报告会脱敏邮箱、账号 ID、Token 类字段，但在公开发布前仍建议人工复核。
- “报障”会生成已脱敏报告；不要附带业务账号凭据、Cookie 或完整源码。

## 9. 导入导出与备份恢复

| 操作 | 说明 |
|---|---|
| 导出账号 | 包含账号信息与凭据密文，用于迁移；可能含敏感数据，妥善保管 |
| 导入账号 | 按 Account ID 合并；只更新别名/邮箱/凭据，保留现有 Worker 清单与其他元数据；整份验证失败则零写入 |
| 下载备份 | 面板提供的配置备份；authority 模式下完整权威恢复需要独立维护通道 |
| 恢复备份 | 会覆盖对应配置；恢复前先核对外部资源与当前权威状态 |
| 旧 KV 恢复 | authority 模式下被拒绝（409），避免用陈旧 KV 回退 |

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| 401 / 登录过期 | 重新登录同一 HTTPS 源站，保留原任务 ID |
| 403 / CSRF | 检查源站与会话，不要关闭安全校验 |
| 400 / INVALID | 核对目标、模板、保护策略、日期范围与大小边界；附脱敏请求 ID 排查 |
| 409 | 区分配置基线冲突、同键异意图、任务状态屏障；先读取原状态 |
| 428 | 页面/客户端协议旧；刷新/更新前端，不要绕过协议 |
| 503 / NOT_READY | DO/Secret/pin 等权威配置未就绪或正在维护；不要回退旧 KV |
| unknown | 停止新的写操作，保留原任务/日志，由维护人员观察和裁决 |
| 兼容日期保存失败 | 检查日期是否在 2021-11-01 至今天之间；409 时刷新后重试 |
| Worker 上传报 1101 | 走 1101 修复，不要手动反复上传；先备份 |

## 11. 安全建议

- 使用最小权限的 Cloudflare API Token；不要用全局 Key 长期运行。
- `ACCESS_CODE` 与业务账号凭据分开保管；不要在聊天/Issue 中粘贴。
- 定期导出账号或做受控备份；但备份文件本身要按敏感数据保存。
- 面板发布新版本后刷新页面，避免旧前端协议与旧草稿冲突。
